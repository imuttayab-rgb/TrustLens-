# TrustLens search and Pakistan locations update

Prepared 3 October 2026. This is a source-only update on top of the installed AI + Home package and the approved five-question FAQ update.

## Behavior

- Home uses **Suggested searches**. These are curated Pakistan marketplace terms, not measured popularity. Search analytics do not exist in this release, so the UI does not assert a ranking or fabricated demand.
- Autocomplete covers all 14 existing categories with 1,056 category, family, brand, model and product-type entries. Mobile brand labels include **Mobile Phones**. A generic laptop query shows HP, Dell, Lenovo, Apple MacBooks and Chromebooks. HP has more than 10 real model entries. iPhone generations list their actual variants, not a Cartesian product of imagined Pro/Mini/Plus names.
- Ten suggestions load initially; **Show more suggestions** appends the next page. Catalogue choices use a separate canonical query and category. Eligible public listing titles supplement the catalogue; sellers use vocabulary without borrowing another seller's title. Catalogue suggestions are not a claim that inventory exists.
- Common aliases include `i phone`, `mac book`, `chrome book`, `techno`, `Hewlett-Packard` and `PS 5`. Matching ignores case, normalizes plurals and separates attached model numbers. Keyboard arrows/Enter/Escape, click and touch selection work. Requests are debounced and aborted on query changes; pagination is bounded. No model or internet-search request runs on keystrokes.
- All four provinces plus **Azad Jammu and Kashmir**, **Gilgit-Baltistan** and **Islamabad Capital Territory** appear under **Province / region**. Both regions and city/town names are A–Z. The filtered extract has **561 region/place entries**, with repeated names deduplicated inside each region. Some places in different regions share names.
- Region selection narrows the city picker in Home, Browse and Post an Ad. Changing region clears the previous city; Home and Browse require a city before applying that location. The existing backend filters by city, so province-wide filtering is not silently implied. Post an Ad also clears an old map pin when changing city/region. Existing neighbourhood lists are preserved; Other remains available for missing locations.
- Native option text/background colors are explicit in both themes, fixing unreadable unselected options on dark-mode dropdowns.
- Footwear remains inside Fashion & Beauty; it is not suggested for a mobile-phone category.

## Sources and data limits

The catalogue is maintained search vocabulary, not an exhaustive worldwide product/SKU database, live pricing feed, specification reference or availability guarantee. Actual listing titles can surface models outside the catalogue. Unlisted terms can always be typed. Model families such as HP Pavilion 15 represent families, not a promise that every generation/configuration is included. No prices, RAM/storage claims or seller condition claims are generated by this catalogue.

### Location attribution

City/region data adapted from **GeoNames**, https://www.geonames.org/, downloaded 3 October 2026, licensed under **Creative Commons Attribution 4.0**, https://creativecommons.org/licenses/by/4.0/.

Source: https://download.geonames.org/export/dump/PK.zip ; schema/admin mapping: https://download.geonames.org/export/dump/readme.txt and https://download.geonames.org/export/dump/admin1CodesASCII.txt . Source coverage is Pakistan populated places over 500 population or administrative seats down to PPLA4. Abandoned/historical places and city sections were excluded. Duplicate names were removed per region; a few familiar spellings were standardized (e.g. Vehari, Sheikhupura, Mirpur, Athmuqam, Miranshah, Nagar, Shahdadkot). The original ten app city names are preserved.

This is not every village, an official census, or a boundary/legal statement. GeoNames supplies data as-is. Existing listings store city names without province IDs, so same-named places across regions remain an existing limitation. Neighbourhood coverage remains the original ten cities; this update does not invent locality lists.

## Installation and recovery

Download `TrustLens_Search_Location_Update.sh` to Windows Downloads, start Docker Desktop and the existing TrustLens app, then run in Git Bash:

```bash
bash "$HOME/Downloads/TrustLens_Search_Location_Update.sh"
```

The installer verifies source hashes before modifying files, backs up old sources and API/web images, builds API + web, checks local health and exercises the installed catalogue without provider calls. It never asks for API keys or edits environment files. API settings, verification flags, uploaded files, database, worker, admin and the five FAQ questions are preserved. No migration, seed, volume deletion, git reset, dependency additions or paid fallback.

A build may take several minutes; a progress heartbeat and log path are shown. On failure, rollback restores source and previous API/web images. Newer source edits block rollback instead of being overwritten. The final output prints the exact recovery script path under `.git/trustlens-search-backups/`.

After success, open http://localhost:3000 and press Ctrl+Shift+R. Only report the laptop update installed after its own success output; local development checks do not establish that the user's Docker instance has been updated.
