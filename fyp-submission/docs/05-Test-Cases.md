## 1. Test plan

### 1.1 Objectives

- Verify that the Trust Score engine computes scores correctly, including edge cases (unavailable
  signals, insufficient evidence, hard caps, boundary values at band edges).
- Verify authentication, authorization, and the RBAC permission matrix hold under adversarial input
  (IDOR, privilege escalation, token reuse).
- Verify the explainability guarantee: every score's breakdown is reconstructable without
  recomputation.
- Verify the public API never leaks PII and behaves correctly under rate limiting and revoked keys.
- Honestly record what has and has not been verified, so the FYP evaluation committee can calibrate
  confidence correctly.

### 1.2 Scope

**In scope:** functional correctness of the scoring engine, authentication/authorization, identity
and contact verification flows, appeals, the public API contract, and the security controls listed
in `docs/15-security.md`.

**Explicitly out of scope for this test plan:**

- **Real-world OCR/face-match accuracy.** No consented real CNIC image set exists yet (tracked as
  P1-01/P1-06 in the project's own task list). All AI-evaluation testing described in §4.6 runs
  against synthetic or public-research fixtures, never real identity documents, by design (`docs/14-testing-strategy.md`
  §6, §10 — "No real CNIC images ever enter the repository").
- **Production load/performance validation.** The latency targets in the SRS (§6.1) are design
  targets; no load test has been run against deployed infrastructure, because nothing is deployed
  (§11.3 of the SDD).
- **Independent penetration testing.** Only automated scans (ZAP baseline, dependency audits) have
  run; no manual pentest was performed.

### 1.3 Test levels

Unit (pytest/Vitest) → Integration (testcontainers against real Postgres/Redis) → API (httpx against
the live ASGI app) → Contract (Schemathesis fuzzing the OpenAPI schema) → E2E (Playwright) → AI/ML
evaluation (aggregate metrics, not per-output assertions) → Security (ZAP, dependency scans, the
authorization matrix test) → Load (k6, not yet run). Full shape and targets: `docs/14-testing-strategy.md`.

### 1.4 Entry / exit criteria

|                                       | Criterion                                                                                                               |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Entry                                 | Feature's use case is implemented and passes local `make test-unit`                                                     |
| Exit (per PR)                         | Full CI green: lint, typecheck, arch contracts, unit, integration, build, codegen-drift, migration check, security scan |
| Exit (release-ready, not yet reached) | E2E green on both Chromium and WebKit, load test targets met, manual RBAC review complete, dependency scan clean        |

### 1.5 Pass/fail criteria

A test case passes only when the **actual** observed result matches the **expected** result exactly,
including error codes and messages where specified. A case that "mostly works" or "works but with a
wrong error code" is a **fail**, logged as a defect, not a qualified pass.

### 1.6 Risks and mitigations

| Risk                                                                                         | Mitigation                                                                                                                                                                |
| -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Manual QA pass (Stage 6 in `REMAINING.md`) has not yet run at the time of this documentation | This document states that honestly rather than fabricating results; §5 shows the real specified/executed split                                                            |
| The scam classifier is measurably weak on real target-domain text                            | Kept out of live scoring (`max(llm_risk, classifier×100)` is computed but the classifier is not yet a scoring input) until P7-02 (labelled Pakistani-ad data) is resolved |
| No real CNIC/face accuracy numbers                                                           | Stated as an explicit out-of-scope item (§1.2) rather than assumed acceptable                                                                                             |
